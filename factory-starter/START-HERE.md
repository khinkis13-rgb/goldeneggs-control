# Старт здесь — каркас «Фабрики контента»

Это стартовый проект-каркас поверх готового движка автопубликации в Instagram. Он **намеренно нейтральный**: переименуйте, перекрасьте, перепишите UI под себя. Движок (публикация, токены, аккаунты) — не ваша забота, он уже работает; вы строите свою часть поверх него.

Откройте `index.html` в браузере — это рабочий каркас. Вкладка **«Внедрение / Roadmap»** внутри него дублирует эту дорожную карту. Каждый раздел приложения сам объясняет, что он делает и что с ним делать дальше.

## Граница зон (главное, что нужно понять)

| | Движок (наша зона) | Фабрика (ваша зона) |
|---|---|---|
| Что | Публикация в IG, токены Meta, подключённые аккаунты, реестр аккаунтов | UI, организация контента по командам/разделам, ваше хранилище, планировщик |
| Как трогаете | Через HTTP API (см. `../docs/API.md`) | Это весь этот проект — форкаете и достраиваете |
| Кто заводит аккаунты | Мы — по запросу (см. `../docs/ONBOARDING-ACCOUNT.md`) | Вы присылаете нам тему/требования, получаете готовый `account_id` |

Вы **не** держите токены, **не** настраиваете Meta, **не** видите чужой контент. Вы присылаете «опубликуй вот это в такой-то аккаунт» — движок публикует.

## Легенда статусов (та же, что в каркасе)

- ✅ **РАБОТАЕТ ВЖИВУЮ** — реально дёргает движок, можно пользоваться сразу.
- 🟡 **ДЕМО-ЗАГЛУШКА** — данные-примеры в JS (`SAMPLE_SECTIONS`), замените на своё хранилище.
- 🔧 **ВАМ ПОСТРОИТЬ** — функциональность, которую достраиваете вы.

## Быстрый старт (5 минут)

1. Запросите у команды движка три вещи: **URL Web App**, ваш **API-ключ**, ваши **account_id** (для отладки — тестовый `sandbox`).
2. Откройте `index.html` → вкладка **Настройки** → впишите URL, ключ, `folderUrl` (папка Google Drive для загрузки медиа) и список `account_id` (по одному в строке). Сохраните — данные лягут в localStorage браузера.
3. Нажмите **«Проверить связь»** (вкладка Настройки) — ждём `{ "ok": true }`. Если `PIN_REQUIRED` — неверный ключ; если связь не идёт — проверьте URL.
4. Откройте редактор поста → выберите `sandbox` → **«Загрузить медиа»** (картинка) → **«Подставить в mediaUrls»** → **«Опубликовать сейчас»**. В Журнале увидите `igPostId` и `permalink`.

Если это сработало — связка живая, дальше только ваша надстройка.

## Дорожная карта внедрения

- [ ] **Шаг 1. Подключиться.** Доступы в Настройки → `ping` зелёный. ✅ *(каркас готов)*
- [ ] **Шаг 2. Проверить публикацию.** Тестовый пост в `sandbox` через `publishNow`. ✅ *(каркас готов)*
- [ ] **Шаг 3. Своё хранилище контента.** Замените демо-массив `SAMPLE_SECTIONS` (в `index.html`, помечено `// TODO(шаг 3)`) на вашу БД / таблицу / API. Формат поста: `{ accountId, mediaType: 'photo'|'reels', mediaUrls: [], videoUrl, caption, date, status }`. 🟡→✅
- [ ] **Шаг 4. Своя UI и айдентика.** Перекрасьте, переименуйте, перекомпонуйте. Каркас — донор связей, не финальный дизайн. Главное — сохраните контракт запросов к движку. 🔧
- [ ] **Шаг 5. Планировщик.** Календарь в каркасе — слой планирования; сам он по времени НЕ публикует (см. ниже). 🔧
- [ ] **Шаг 6. Масштаб на команды/аккаунты.** Разные разделы → разные `account_id`. Новый аккаунт запрашиваете у нас, мы выдаём `account_id` и (при необходимости) отдельный ключ. 🔧

## Шаг 5 подробно — планировщик (почему это заглушка и как построить)

Движок умеет публиковать **только по команде `publishNow`** (немедленно). Серверное расписание у движка есть, но командным ключам оно закрыто. Значит автопубликацию по времени строите вы — это небольшой серверный планировщик:

```
1. Пользователь планирует пост → вы сохраняете его в своей БД
   со статусом 'scheduled' и временем publishAt.
2. Ваш cron (раз в N минут) выбирает посты, у которых publishAt <= сейчас
   и статус == 'scheduled'.
3. Для каждого — POST на URL движка с телом:
   { action:'publishNow', apiKey:'<ваш ключ>', accountId:'<...>',
     mediaType:'photo'|'reels', mediaUrls:[...] | videoUrl:'...', caption:'...' }
4. По ответу ok=true → статус 'published' (сохраните igPostId/permalink);
   ошибка → ретрай / статус 'error'.
```

В каркасе это место — функция `scheduleStub()` в `index.html` (с этим же псевдокодом в комментарии). Кнопка «Запланировать» сейчас только помечает пост локально и показывает эту подсказку.

## Что доступно вашему ключу (и чего нет)

Командный ключ может **только**: `ping`, `upload`, `publishNow` — и только в свои `account_id`. Всё остальное вернёт `ACTION_NOT_ALLOWED`, чужой аккаунт — `ACCESS_DENIED`. Поэтому:

- Чтения списка постов «с движка» нет — источник правды по контенту **ваш** (Шаг 3).
- Публикация сейчас идёт в **Instagram** (лента: фото/карусель; Reels). Facebook и прочее — на будущее.
- `account_id` всегда передавайте явно.
- Reels публикуется синхронно, до ~2.5 минут — не шлите повторно, дождитесь ответа.

Полный контракт, все поля, опции (`collaborators`, `locationId`, `altText`, `firstComment`, `coverUrl`, `shareToFeed`) и коды ошибок — в **`../docs/API.md`**.

## Когда нужен новый аккаунт

Присылаете нам тему/назначение. Мы заводим аккаунт по `../docs/ONBOARDING-ACCOUNT.md`, добавляем его в реестр и выдаём вам `account_id`. Дальше вы просто указываете его в постах.
