## 1. Обзор

### Что такое движок

Golden Eggs — это движок автопубликации в **Instagram** и **Facebook**, реализованный как Google Apps Script Web App. Связку с Meta (System User токен, подключённые аккаунты, акт публикации) держим **мы**. Вы строите свой UI, организацию по командам и график — поверх нашего HTTP API.

Граница ответственности:

- **Ваша зона:** интерфейс, разделы/команды, контент, ваш собственный график публикаций.
- **Наша зона:** токен Meta (он не покидает наш контур), сам акт публикации, онбординг каждого нового аккаунта (см. `docs/ONBOARDING-ACCOUNT.md`).

### Транспорт

- **Метод:** только `POST`. `GET` отключён намеренно (возвращает `{ok:false, error:"GET disabled. Use POST with PIN."}`).
- **URL:** Web App вида `https://script.google.com/macros/s/.../exec` (выдаём вам отдельно).
- **Тело запроса:** JSON. Поле `action` выбирает действие.
- **Content-Type:** при `fetch` из браузера используйте `text/plain;charset=utf-8` — это позволяет Apps Script Web App принять тело без CORS-preflight. Apps Script всё равно парсит тело как JSON (`JSON.parse(e.postData.contents)`).

> Примечание: если тело не парсится как JSON, движок молча использует пустой payload `{}` — запрос дойдёт до проверки авторизации и вернёт `PIN_REQUIRED`.

### Базовый формат запроса

```json
{
  "apiKey": "ваш_ключ",
  "action": "publishNow",
  "accountId": "ваш_account_id",
  "...": "поля действия"
}
```

### Базовый формат ответа

Всегда JSON. Успех:

```json
{ "ok": true, "...": "поля результата" }
```

Ошибка:

```json
{ "ok": false, "error": "человекочитаемый текст", "code": "MACHINE_CODE" }
```

> Поле `code` присутствует только у трёх «контрактных» ошибок авторизации (`PIN_REQUIRED`, `ACTION_NOT_ALLOWED`, `ACCESS_DENIED`). У прочих ошибок (ошибки Meta, валидация полей, неизвестное действие) есть только `error` без `code` — см. раздел 2.

### Аутентификация по `apiKey`

Для Фабрики аутентификация — по полю **`apiKey`** в теле запроса. Ключи и их разрешения задаём **мы** (хранятся в Script Property `API_KEYS`, в JSON). Вы получаете от нас готовый ключ и список своих `account_id`.

К каждому ключу привязано:

- **`accounts`** — список разрешённых `account_id` (или `"*"` для доверенной интеграции, что вам по умолчанию не выдаётся).
- **`actions`** — белый список действий. Если мы не указали его явно, ключу доступны **только** действия из дефолтного набора:

  ```
  upload, publishNow, ping
  ```

  Это и есть рабочий контракт Фабрики. Все остальные действия (чтение нашего листа, расписание, профили и т.д.) ключу по умолчанию запрещены — см. раздел 5.

> Существует также внутренний админ-доступ нашего дашборда (поле `pin`, мастер-доступ ко всем аккаунтам и действиям). Он **не** является частью публичного контракта — Фабрика работает только по `apiKey`.

### Что такое `account_id`

`account_id` — идентификатор аккаунта публикации (один System User токен публикует во много IG-аккаунтов, отличаются только `ig_user_id`). Реестр аккаунтов живёт в листе `аккаунты`, которым управляем **мы**: `account_id | label | ig_user_id | fb_page_id | команда | статус`. Аккаунт должен иметь статус `active`.

Вы просто ссылаетесь на выданные вам id в поле `accountId` (синоним — `account_id`, оба принимаются). Публикация в аккаунт, не входящий в `accounts` вашего ключа → `ACCESS_DENIED`.

> Если `accountId` не передан, движок подставляет аккаунт по умолчанию `goldeneggs` (обратная совместимость со старым дашбордом). Для Фабрики **всегда передавайте свой `accountId` явно** — иначе при отсутствии `goldeneggs` в `accounts` вашего ключа вы получите `ACCESS_DENIED`.

## 2. Коды ошибок

### Контрактные коды авторизации

Проверки выполняются в `handle_` строго в этом порядке. Возвращаются с полем `code`:

| `code` | HTTP-уровень | Когда возникает | Текст `error` (пример) |
|---|---|---|---|
| `PIN_REQUIRED` | 200, `ok:false` | Нет валидной аутентификации: не передан ни `pin`, ни `apiKey`, либо `apiKey` отсутствует в реестре `API_KEYS`. | `Bad PIN` |
| `ACTION_NOT_ALLOWED` | 200, `ok:false` | Аутентификация прошла, но запрошенное `action` не входит в белый список ключа (по умолчанию — не `upload`/`publishNow`/`ping`). Проверяется **до** выполнения действия. | `Действие «read» не разрешено для этого ключа.` |
| `ACCESS_DENIED` | 200, `ok:false` | Действие разрешено, но запрошенный `account_id` не входит в `accounts` ключа. Касается действий публикации и расписания. | `Нет доступа к аккаунту «acc_b».` |

> Все ответы приходят с HTTP 200 — различать успех/ошибку нужно по полю `ok`, а тип ошибки — по `code`. Это поведение Apps Script `ContentService`.

> Пустое `action` трактуется как `read` (и в проверке прав, и в диспатче). Для командного ключа без права `read` это даст `ACTION_NOT_ALLOWED` с текстом про действие `read`.

### Ошибки без `code`

- **Неизвестное действие:** `{ ok:false, error: "unknown action: <action>" }` (без `code`).
- **Валидация полей действия:** например `{ ok:false, error: "Нет данных файла" }`, `{ ok:false, error: "Нет медиа для публикации." }` — текст бросается внутри функции-обработчика, `code` нет.

### Ошибки Meta (Graph API)

Любая ошибка от Meta при публикации проходит через `igGraphPost_` и превращается в исключение, которое `handle_` отдаёт как `{ ok:false, error: "..." }` **без `code`**. Формат текста:

```
Instagram: <message> — <error_user_msg> (code <code>/<error_subcode>)
```

Примеры реальных текстов из кода:

- `Instagram: <текст ошибки Meta> (code 190)` — например невалидный токен.
- `Временный сбой Instagram (...). Это не про ваше видео — просто нажмите «Опубликовать» ещё раз через 1–2 минуты.` — коды Meta `2207082` / `2207001` при обработке видео (движок уже делает один авто-повтор; если не помогло — повторите запрос).
- `Instagram не смог обработать видео: <status>. Проверьте формат: MP4/MOV (H.264 + AAC), вертикаль 9:16, 3–90 c.` — контейнер Reels ушёл в `ERROR`.
- `Instagram слишком долго обрабатывает видео (>2.5 мин)...` — таймаут поллинга готовности Reels (30 попыток × 5 c).
- `Видео ... — больше 100 МБ Google Drive не отдаёт напрямую...` — видео > 100 МБ (см. раздел 4).

> Разбирайте ошибки Meta по подстроке/`code` в тексте — отдельного машинного поля для них нет. Это ограничение текущей реализации.

## 3. Действия для Фабрики

Доступны командному ключу по умолчанию: `ping`, `upload`, `publishNow`.

### 3.1 `ping` — проверка связи

Проверяет доступность движка и валидность ключа. Не требует `accountId`.

**Запрос:**

```json
{ "apiKey": "ваш_ключ", "action": "ping" }
```

**Ответ:**

```json
{ "ok": true }
```

> `ping` проходит проверку `authAllowsAction_` как обычное действие. Если у вашего ключа сужен список `actions` и в нём нет `ping` — вернётся `ACTION_NOT_ALLOWED`. В дефолтном наборе `ping` есть.

**Пример (fetch):**

```js
await fetch(WEBAPP_URL, {
  method: "POST",
  headers: { "Content-Type": "text/plain;charset=utf-8" },
  body: JSON.stringify({ apiKey: API_KEY, action: "ping" })
}).then(r => r.json());
```

---

### 3.2 `upload` — загрузка медиа

Загружает один файл (картинку или видео) в наше хранилище Google Drive и возвращает публичную ссылку. Полученный `url` затем передаётся в `publishNow` как `mediaUrl` / `videoUrl`.

**Поля запроса** (из `uploadFile_`):

| Поле | Тип | Обяз. | Описание |
|---|---|---|---|
| `apiKey` | string | да | Ваш ключ. |
| `action` | string | да | `"upload"`. |
| `dataBase64` | string | да | Содержимое файла в base64 (без префикса `data:...;base64,`). Без него — `error: "Нет данных файла"`. |
| `folderUrl` | string | да | URL папки Google Drive, куда класть файл. Без неё — `error: "Не указана папка Drive (в Настройках пульта)"`. Из URL извлекается id по шаблону `folders/<id>`; если не распознан — `error: "Не получилось распознать папку Drive в URL"`. |
| `mimeType` | string | нет | MIME-тип файла (например `image/jpeg`, `video/mp4`). По умолчанию `application/octet-stream`. **Важно для публикации:** тип медиа (фото vs видео) дальше определяется по Drive MIME, поэтому корректный `mimeType` желателен. |
| `filename` | string | нет | Имя файла. По умолчанию `upload`. |

> Ограничение: папку Drive (`folderUrl`) движок берёт из payload, отдельной серверной настройки папки на ключ/аккаунт сейчас нет. Папку для загрузок мы согласуем с вами отдельно. Файл получает доступ `ANYONE_WITH_LINK` (view).

**Ответ** (из `handle_`):

```json
{
  "ok": true,
  "url": "https://drive.google.com/file/d/<fileId>/view",
  "fileId": "<fileId>",
  "name": "<имя файла>"
}
```

> `url` возвращается в формате `.../file/d/<id>/view`. Это нормально: при публикации движок сам извлекает Drive-id из любой такой ссылки и строит прямой URL, который скачивает Meta (для фото — `lh3.googleusercontent.com/d/<id>=w1440`, для видео — `drive.usercontent.google.com/download?...`). Передавайте в `publishNow` именно полученный `url`.

**Пример (fetch):**

```js
const res = await fetch(WEBAPP_URL, {
  method: "POST",
  headers: { "Content-Type": "text/plain;charset=utf-8" },
  body: JSON.stringify({
    apiKey: API_KEY,
    action: "upload",
    dataBase64: base64String,
    mimeType: "image/jpeg",
    filename: "post-1.jpg",
    folderUrl: "https://drive.google.com/drive/folders/XXXX"
  })
}).then(r => r.json());
// res.url -> кладём в publishNow.mediaUrl
```

### 3.3 `publishNow` — немедленная публикация

Публикует пост в Instagram прямо сейчас, в указанный `accountId`. Это тонкий алиас над логикой публикации фото/карусели (`publishInstagram_`) и Reels (`publishInstagramReels_`).

#### Маршрутизация фото vs Reels (`publishNow_`)

Движок выбирает Reels, если выполнено **любое** из условий:

- передан `videoUrl`, **или**
- `mediaType` равен `"reels"` или `"video"` (регистр не важен).

Иначе — маршрут на фото/карусель (`publishInstagram_`). При маршруте на фото, если медиа берётся из `mediaUrls`, тип каждого файла дополнительно авто-детектится по Drive MIME: одиночное видео в `mediaUrls` тоже уедет как Reels; видео + фото вместе → ошибка `Видео публикуется только по одному (как Reels)...`.

#### Поля запроса

| Поле | Тип | Описание |
|---|---|---|
| `apiKey` | string | Ваш ключ. |
| `action` | string | `"publishNow"`. |
| `accountId` / `account_id` | string | Куда публиковать. Оба имени принимаются (`payload.accountId \|\| payload.account_id`). Должен входить в `accounts` ключа, иначе `ACCESS_DENIED`. |
| `mediaType` | string | Опц. Хинт маршрутизации: `"reels"`/`"video"` форсируют Reels. Для фото можно не передавать. |
| `videoUrl` | string | URL видео для Reels. Его наличие форсирует маршрут Reels. |
| `mediaUrls` | string[] | Массив URL фото для фото/карусели. 1 элемент → одиночное фото; 2+ → карусель. URL могут содержать `#`-метаданные (имя/размер) — движок их отрезает. |
| `caption` | string | Подпись. Если не передать (`undefined`/`null`) и указан `rowIndex` — соберётся из строки листа; иначе пустая. |
| `rowIndex` | number | Опц. Номер строки нашего листа `инст`. Если задан — служит fallback-источником медиа/подписи/опций и **местом записи результата** (статус `published`, `ig_post_id`, ссылка). Для Фабрики, которая держит свой контент у себя, обычно **не нужен** — передавайте медиа и `caption` напрямую. |
| `options` | object | Опц. Опции IG-публикации (см. ниже). |

> Замечание про `mediaUrl` (единственное число): в коде `publishInstagram_` читает **`mediaUrls`** (массив), не `mediaUrl`. Для фото передавайте массив `mediaUrls: ["..."]`. Для видео — строку `videoUrl: "..."`.

#### Опции публикации (`payload.options`)

`publishNow` принимает объект `options`. **Если `options` не передан и задан `rowIndex`**, опции собираются из колонок строки листа (`igOptionsFromRow_`). Поля объекта `options` (имена сверены с `igAddParentOpts_` / `igAddPhotoOpts_` / `igCreateReelsContainer_`):

| Поле `options` | Тип | Применяется к | Поведение в коде |
|---|---|---|---|
| `collaborators` | string[] | одиночное фото, родитель карусели, Reels | Соавторы. **Максимум 3** — лишние молча отбрасываются (`.slice(0, 3)`). Не применяется к детям карусели. Передавайте массив username без `@`. |
| `locationId` | string | то же, что соавторы | Идёт в Graph как `location_id`. Это **ID локации Meta**, не название. |
| `userTags` | string[] | фото-контейнеры (одиночное фото и дети карусели) | Отметки людей. Каждый username превращается в `{username, x:0.5, y:0.5}` — **координаты захардкожены в центр (0.5, 0.5)**, своих координат API не принимает (ограничение реализации). |
| `altText` | string | фото-контейнеры | Alt-текст (`alt_text`). |
| `firstComment` | string | после публикации | Первый комментарий к посту (обычно хэштеги). Отправляется отдельным запросом; **некритично** — при ошибке публикация остаётся, ошибка только логируется. |
| `coverUrl` | string | только Reels | Своя обложка Reels (`cover_url`). Если не передана, но задан `rowIndex` — берётся из колонки «Обложка» строки. |
| `shareToFeed` | boolean | только Reels | `true` → `share_to_feed=true`, `false` → `false`. Если не задано — параметр не отправляется (дефолт Meta = в ленте). |

> **Ограничение текущей реализации.** Когда `options` **не** передан в payload, но указан `rowIndex`, соавторы / `locationId` / `userTags` / `altText` / обложка Reels / `shareToFeed` читаются **из колонок строки листа** (`igOptionsFromRow_`), а не из payload. Поскольку Фабрика держит контент у себя и обычно публикует **без `rowIndex`**, единственный способ задать эти опции — передать их в `options` напрямую. Без `rowIndex` и без `options` пост уйдёт без доп-опций.
>
> **Первый комментарий из строки** (`buildCaptionAndOptions_`): флаг «хэштеги первым комментом» и сам текст комментария собираются только при работе через `rowIndex`. При прямой публикации задавайте `options.firstComment` сами; авто-выноса хэштегов из `caption` в комментарий без `rowIndex` нет.

#### Ответ

Для фото/карусели и Reels одинаковый (из `handle_`):

```json
{
  "ok": true,
  "igPostId": "<id опубликованного медиа>",
  "permalink": "<ссылка на пост>"
}
```

> `permalink` тянется отдельным запросом (`igPermalink_`) и **некритичен**: при ошибке его получения вернётся пустая строка `""`, но `igPostId` будет валидным и пост опубликованным. Не полагайтесь на непустой `permalink`.

#### Поведение Reels (асинхронность)

Видео обрабатывается Meta асинхронно, поэтому вызов `publishNow` с видео **блокирующий и длительный**:

1. Создаётся REELS-контейнер (`igCreateReelsContainer_`).
2. Движок **поллит готовность** контейнера (`igWaitContainerReady_`): до **30 попыток × 5 секунд = до ~150 c**, пока `status_code` не станет `FINISHED`. На `ERROR` — читаемая ошибка; на таймаут — ошибка «слишком долго обрабатывает видео».
3. На временный сбой Meta (`2207082`/`2207001`) делается **один авто-повтор** всего цикла (с паузой 15 c) — публикации до этого момента ещё нет, повтор безопасен.
4. После готовности — `media_publish`, затем первый комментарий и permalink.

> **Практическое следствие для UI.** HTTP-ответ на Reels может прийти через ~1–2.5 минуты. Ставьте клиентский таймаут с запасом (Apps Script ограничен 6 минутами на выполнение). Отдельного асинхронного эндпоинта со «статусом задачи» **нет** — ответ приходит синхронно, когда публикация завершена либо упала с ошибкой. Фото публикуется быстро (без поллинга).

#### Пример (fetch) — фото

```js
await fetch(WEBAPP_URL, {
  method: "POST",
  headers: { "Content-Type": "text/plain;charset=utf-8" },
  body: JSON.stringify({
    apiKey: API_KEY,
    action: "publishNow",
    accountId: "acc_a",
    mediaUrls: ["https://drive.google.com/file/d/FILE_ID/view"],
    caption: "Текст поста\n\n#хэштег1 #хэштег2",
    options: {
      collaborators: ["partner_account"],
      locationId: "123456789",
      altText: "Описание изображения",
      firstComment: "#ещё #хэштеги"
    }
  })
}).then(r => r.json());
```

#### Пример (fetch) — Reels

```js
await fetch(WEBAPP_URL, {

```

```bash
curl -L -X POST "$WEBAPP_URL" \

    "accountId": "acc_a",
    "mediaUrls": ["https://drive.google.com/file/d/FILE_ID/view"],
    "caption": "Текст поста"
  }'
```

> Флаг `-L` обязателен: Apps Script Web App отвечает редиректом на `script.googleusercontent.com`.

## 4. Требования к медиа

- **Публичный URL.** Meta скачивает медиа по ссылке, поэтому файл должен быть публично доступен. Загруженные через `upload` файлы получают доступ `ANYONE_WITH_LINK` автоматически. Если передаёте свою ссылку — она должна отдавать **сами байты** файла, а не HTML-страницу.
- **Прямые ссылки Google Drive** (движок строит их сам из Drive-id):
  - **Фото:** `https://lh3.googleusercontent.com/d/<id>=w1440` (полноразмерный JPEG/PNG; thumbnail `sz=w400` Meta не скачает).
  - **Видео:** `https://drive.usercontent.google.com/download?id=<id>&export=download&confirm=t` (отдаёт байты без редиректа и без антивирусной заглушки для файлов до ~100 МБ).
- **Версия Graph API:** `v23.0` (константа `GRAPH_VERSION`), хост `https://graph.facebook.com/`.
- **Видимые в коде лимиты и требования:**
  - **Видео ≤ 100 МБ.** Больше — Google Drive отдаёт антивирусную заглушку (HTML) вместо файла, Meta не скачивает (ошибка проверяется заранее, понятный текст).
  - **Формат видео для Reels:** MP4/MOV (H.264 + AAC), вертикаль 9:16, длительность 3–90 c (из текста ошибки при `ERROR`).
  - **Соавторы:** максимум 3 (лишние отбрасываются).
  - **Карусель:** 2+ фото = карусель; одиночное фото = обычный пост. Видео в карусели **не поддерживается** — видео публикуется только по одному, как Reels.
  - **Соотношение сторон фото:** Meta принимает примерно 4:5 … 1.91:1 (из диагностического текста; жёсткой проверки на стороне движка нет — отвергает Meta).
  - **Таймаут обработки Reels:** до ~150 c поллинга, затем ошибка.

## 5. Что есть в движке, но недоступно командным ключам

Кроме `ping`/`upload`/`publishNow`, в `handle_` реализованы и другие действия, но они **по умолчанию запрещены** командному ключу (вернут `ACTION_NOT_ALLOWED`). Это внутренний / админский слой нашего дашборда поверх листа `инст`:

| Действие | Назначение (внутреннее) |
|---|---|
| `read` (или пустое `action`) | Чтение всех постов нашего листа `инст`. |
| `create` | Создать строку поста. |
| `update` | Изменить поле строки. |
| `delete` | Удалить строку. |
| `publishInstagram` | Прямая публикация фото/карусели (низкоуровневый аналог `publishNow`). |
| `publishInstagramReels` | Прямая публикация Reels. |
| `schedulePost` | Поставить строку в очередь автопубликации (по `datetime` строки). |
| `unschedulePost` | Снять строку с автопубликации. |
| `readProfiles` / `saveProfile` / `saveHighlight` / `deleteHighlight` | Управление вкладкой «Страницы» (профили, highlights). |
| `zipMedia` | Собрать список медиа в один ZIP-архив на Drive. |

Эти действия завязаны на **наш** лист `инст` и не предназначены для внешних команд (в частности, `read`/`readProfiles` намеренно закрыты, чтобы чужая команда не видела наш контент).

> **Возможное расширение (не реализовано как контракт для Фабрики).** В движке есть рабочий планировщик: триггер `runScheduledPublishing` раз в 5 минут публикует строки со статусом `scheduled`, чьё время наступило, и берёт `account_id` из строки. Действия `schedulePost`/`unschedulePost` тоже проверяют доступ к аккаунту. Но они работают **через строки нашего листа `инст`** — отдельного «серверного расписания по API» для внешнего контента сейчас нет. Если Фабрике понадобится серверная очередь (вместо собственного планировщика у вас), это **отдельная доработка** с нашей стороны: либо расширение прав вашего ключа на `schedulePost` + договорённость о записи в лист, либо новый эндпоинт. Не закладывайтесь на текущие `schedule*` как на готовый контракт.

## 6. Quickstart

Три шага: `ping` → `upload` → `publishNow`. Подставьте свой `WEBAPP_URL`, `API_KEY`, `accountId` и `folderUrl`.

**Шаг 1 — проверка связи:**

```json
{ "apiKey": "ВАШ_КЛЮЧ", "action": "ping" }
```

Ожидаем `{ "ok": true }`.

**Шаг 2 — загрузка картинки:**

```json
{
  "apiKey": "ВАШ_КЛЮЧ",
  "action": "upload",
  "dataBase64": "<base64 без префикса data:>",
  "mimeType": "image/jpeg",
  "filename": "post-1.jpg",
  "folderUrl": "https://drive.google.com/drive/folders/ВАША_ПАПКА"
}
```

Ответ:

```json
{ "ok": true, "url": "https://drive.google.com/file/d/FILE_ID/view", "fileId": "FILE_ID", "name": "post-1.jpg" }
```

**Шаг 3 — публикация фото:**

```json
{
  "apiKey": "ВАШ_КЛЮЧ",
  "action": "publishNow",
  "accountId": "ВАШ_ACCOUNT_ID",
  "mediaUrls": ["https://drive.google.com/file/d/FILE_ID/view"],
  "caption": "Первый пост через API\n\n#golden #eggs"
}
```

Ответ:

```json
{ "ok": true, "igPostId": "17xxxxxxxxxxxxxxx", "permalink": "https://www.instagram.com/p/XXXX/" }
```

Для Reels на шаге 3 загрузите видео (`upload` с `mimeType: "video/mp4"`), затем вызовите `publishNow` с `mediaType: "reels"` и `videoUrl` вместо `mediaUrls` — и учитывайте, что ответ придёт через 1–2.5 минуты (см. раздел 3.3).
