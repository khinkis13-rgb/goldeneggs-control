# Онбординг нового аккаунта в систему автопубликации

Runbook нашей команды: как завести новый тематический IG-аккаунт и подключить его к движку автопубликации Golden Eggs, чтобы Фабрика контента могла публиковать в него через наш API.

**Когда применять:** появился новый тематический аккаунт (новая рубрика, новый бренд, новый эксперимент), который нужно публиковать через наш единый System User токен.

**Сколько занимает:** ~20–40 минут, из них большая часть — клики в Meta Business Suite. Кода не трогаем.

---

## Что уже есть (не создаём заново)

Эти вещи общие для всех аккаунтов — они уже настроены и переиспользуются:

- **Бизнес-портфель (Business Manager):** «Золотые яйца | фарфор, бизнес, любовь».
- **System User:** `autopublisher`, ID `61591038298519`, роль **Admin**. Через него публикуется ВСЁ.
- **Токен:** бессрочный (`expires_at = 0` и `data_access_expires_at = 0`), лежит в Script Property `IG_ACCESS_TOKEN`. Новый аккаунт **не требует** нового токена.
- **Версия Graph API:** `v23.0` (константа `GRAPH_VERSION` в `apps_script.gs`).
- **Scopes токена:** `instagram_basic`, `instagram_content_publish`, `pages_show_list`, `pages_read_engagement`, `business_management`.

**Главный факт, на котором держится весь онбординг:** один System User токен публикует в МНОГО IG-аккаунтов. Достаточно, чтобы новый IG был привязан к FB-странице, а страница и IG назначены ассетами System User `autopublisher`. Тогда для публикации движку нужен лишь правильный `ig_user_id` — он берётся из реестра по `account_id`.

## Чеклист онбординга

Девять шагов. Идём строго по порядку — каждый следующий опирается на предыдущий.

### Шаг 1 — FB-страница под тематику

- [ ] Создать новую Facebook-страницу под тематику аккаунта (или взять уже существующую).
- [ ] Убедиться, что **вы (тот, кто делает онбординг) — админ этой страницы**. Без прав админа на странице IG публиковать нельзя (см. «Частые грабли»).

> Зачем: IG Graph API публикует через FB-страницу, к которой привязан IG. Нет страницы — нет публикации.

### Шаг 2 — IG как Business/Creator + привязка к странице

- [ ] Перевести IG-аккаунт в тип **Business** или **Creator** (Настройки IG → Тип аккаунта). Личный (personal) аккаунт API не публикует.
- [ ] Привязать IG к FB-странице из Шага 1 (в настройках IG: «Связанные аккаунты» / через Meta Business Suite → Настройки → Связанные аккаунты).

> Зачем: только Business/Creator IG, привязанный к FB-странице, виден через `instagram_business_account` и доступен для `instagram_content_publish`.

### Шаг 3 — Добавить страницу и IG в наш бизнес-портфель

- [ ] В Meta Business Suite открыть портфель **«Золотые яйца | фарфор, бизнес, любовь»**.
- [ ] Настройки → **Аккаунты → Страницы Facebook** → добавить страницу из Шага 1 в портфель.
- [ ] Настройки → **Аккаунты → Аккаунты Instagram** → добавить/подтвердить IG в портфеле.

> Зачем: System User видит только те ассеты, что принадлежат его бизнес-портфелю.

### Шаг 4 — Назначить страницу и IG ассетами System User

- [ ] Настройки → **Пользователи → Системные пользователи** → выбрать `autopublisher` (ID `61591038298519`).
- [ ] **Назначить ассеты** → выбрать FB-страницу из Шага 1 → выдать **полный доступ** (управление).
- [ ] **Назначить ассеты** → выбрать IG-аккаунт из Шага 2 → выдать **полный доступ**.

> Зачем: токен `autopublisher` опубликует в IG только если и страница, и IG назначены ему как ассеты с полным доступом. Это ровно та же процедура, что мы делали для `@goldeneggs_story` при настройке вечного токена.

### Шаг 5 — Узнать `ig_user_id` и `fb_page_id`

Оба ID берём через Graph API на версии `v23.0`. Удобнее всего — через [Graph API Explorer](https://developers.facebook.com/tools/explorer/), выбрав System User токен `autopublisher`.

**Список страниц System User (даёт `fb_page_id`):**

```
GET https://graph.facebook.com/v23.0/me/accounts?fields=id,name&access_token=<TOKEN>
```

В ответе найдите страницу из Шага 1 по `name` — её `id` это и есть `fb_page_id`.

**IG Business Account по странице (даёт `ig_user_id`):**

```
GET https://graph.facebook.com/v23.0/<fb_page_id>?fields=instagram_business_account{id,username}&access_token=<TOKEN>
```

Поле `instagram_business_account.id` — это `ig_user_id` (именно его движок подставляет в эндпоинты `/<ig_user_id>/media` и `/<ig_user_id>/media_publish`). Заодно сверьте `username` — это нужный аккаунт.

- [ ] Получили `fb_page_id`.
- [ ] Получили `ig_user_id`.
- [ ] Если `instagram_business_account` пустой — IG не Business/Creator или не привязан/не назначен ассетом. Вернитесь к шагам 2–4.

> Токен наружу не выносим. Запрос делаем сами через Explorer; передаём дальше только числовые ID, не сам токен.

### Шаг 6 — Записать строку в реестр (лист `аккаунты`)

Реестр аккаунтов нашей системы — лист **`аккаунты`** в Google-таблице. Строка заголовков ровно такая:

```
account_id | label | ig_user_id | fb_page_id | команда | статус
```

- [ ] Придумать короткий `account_id`: **латиницей, без пробелов** (например `porcelain`, `business_love`, `recipes`). Это стабильный технический ключ — менять его потом дорого, выбираем осмысленно.
- [ ] Заполнить `label` — человекочитаемое название (можно с эмодзи, для глаз).
- [ ] Вставить `ig_user_id` и `fb_page_id` из Шага 5.
- [ ] В `команда` указать отдел-владелец (например `Фабрика контента`).
- [ ] В `статус` поставить `active`.

Пример строки:

| account_id | label | ig_user_id | fb_page_id | команда | статус |
|---|---|---|---|---|---|
| porcelain | Фарфор 🍶 | 17841400000000000 | 100000000000000 | Фабрика контента | active |

> Это финальный шаг настройки самого аккаунта. После него движок умеет маршрутизировать публикации в новый IG по `account_id`.

### Шаг 7 — Выдать Фабрике API-ключ с доступом к этому account_id

- [ ] Добавить новый `account_id` в список разрешённых для ключа той команды, что будет публиковать.

API-ключи живут в Script Property **`API_KEYS`** (JSON `api_key → { команда, allowed_account_ids[] }`). Формат ключей и проверку доступа реализует backend — точные поля смотрите в контракте API (`docs/API.md`). Здесь нам важно одно: пока `account_id` не попал в `allowed_account_ids` ключа команды, её запросы на публикацию в этот аккаунт будут отклонены с ошибкой доступа.

> Если выдаём доступ команде впервые — заводим и сам ключ. Это разовая операция на команду, а не на каждый аккаунт.

### Шаг 8 — Тестовая публикация (приёмка)

- [ ] Сделать тестовую публикацию в новый аккаунт через действие `publishInstagram` с явным полем `accountId`, равным новому `account_id`.
- [ ] Дождаться ответа `{ ok: true, igPostId, permalink }`.
- [ ] Открыть `permalink` и убедиться, что пост реально появился в нужном IG.
- [ ] Если это видео — публикация идёт как Reels асинхронно (`publishInstagramReels`), пост появляется после обработки (поллинг статуса контейнера).
- [ ] Тестовый пост удалить (или оставить, если он осмысленный).

Минимальный пример тела запроса (картинка по прямой ссылке):

```json
{
  "action": "publishInstagram",
  "accountId": "porcelain",
  "caption": "тест онбординга",
  "mediaUrls": ["https://lh3.googleusercontent.com/d/<FILE_ID>=w1440"]
}
```

(Авторизация — по API-ключу команды; точные поля авторизации см. в `docs/API.md`.)

После успешной приёмки аккаунт считается подключённым.

## Частые грабли

- **IG не Business/Creator.** На личном аккаунте `instagram_content_publish` не работает и `instagram_business_account` пустой. Лечится Шагом 2.
- **Нет прав админа на FB-странице.** Публикация в привязанный IG требует, чтобы у публикующего (через System User) был полный доступ к странице. Проверяется Шагами 1 и 4.
- **Страница не в портфеле.** Если FB-страница не добавлена в бизнес-портфель «Золотые яйца | фарфор, бизнес, любовь», System User её «не видит» и назначить ассетом нельзя. Лечится Шагом 3.
- **Ассеты не назначены System User.** Страница/IG есть в портфеле, но не выданы `autopublisher` с полным доступом → `me/accounts` не вернёт страницу, публикация упадёт на правах. Лечится Шагом 4.
- **Пустой `instagram_business_account` в ответе Graph.** Симптом одной из проблем выше (не Business, не привязан, не назначен). Не записывайте такой аккаунт в реестр — сначала почините.
- **`account_id` с пробелами/кириллицей.** Технический ключ должен быть латиницей без пробелов, иначе ломается маршрутизация и сверка с `allowed_account_ids`. Кириллица и эмодзи — только в `label`.
- **Забыли Шаг 7.** Аккаунт в реестре есть, токен публикует, но запросы Фабрики отбиваются по доступу — `account_id` не добавлен в `allowed_account_ids` их ключа.
